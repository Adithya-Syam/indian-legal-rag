# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Run everything from the repo root: config paths such as `config/rag_config.yaml` are relative to the current directory, and scripts add the repo root to `sys.path`.

```bash
pip install -r requirements.txt          # app + tests (CPU only)
pip install -r requirements-train.txt    # optional fine-tuning extras (torch, peft, ...)

python -m pytest                                          # unit tests (pytest.ini skips tests/integration)
python -m pytest tests/test_section_predictor.py::test_murder_facts_predict_bns_103   # single test
python -m pytest tests/integration                        # end-to-end scripts; need Ollama running

python scripts/preprocess_data.py --dataset_path dataset --output_path data/processed --clean_text
python scripts/build_rag_index.py --documents_path dataset --index_path data/rag_index
streamlit run web_app/enhanced_app.py                     # http://localhost:8501
```

`make` targets (`install`, `test`, `lint` = flake8 + black --check, `quick-start`) wrap the same commands. On Windows, `make` is usually unavailable.

Runtime needs a local Ollama server (`ollama pull gemma3`). Environment variables:
- `OLLAMA_MODEL` (default `gemma3:latest`; use `gemma3:1b` on 8 GB RAM machines)
- `OLLAMA_NUM_CTX` (default 16384)

## Architecture

**One LLM for everything.** Every LLM call goes through `src/utils/llm_client.py`: `OllamaClient` makes HTTP calls to `localhost:11434/api/generate`, and `LegalLLMClient` adds the legal prompts. Get it via the module-level singleton `get_legal_llm()`.
- Ollama option names are `num_predict` and `num_ctx`, not `max_tokens`. Without `num_ctx`, Ollama silently truncates long inputs.
- `summarize_legal_text()` splits inputs longer than `CHUNK_CHARS` (30k chars) into chunks, extracts notes from each, then combines them.

**Graceful degradation is a deliberate pattern.** `reasoning/`, `bias/` and `visualization/` import the LLM client inside `try` and set `HAS_LLM`. When Ollama is down they fall back to rule-based output instead of raising. Keep this: unit tests and CI run without Ollama, using mocks.

**Web app.** `web_app/enhanced_app.py` is the only UI. `load_enhanced_system()` (`@st.cache_resource`) builds all components into a `components` dict. The "Enhanced Legal Chat" flow:
- runs modules conditionally, based on **keyword triggers** in the user's message (chain-of-thought, section prediction, dual-view summary);
- always produces the main answer through `MultilingualLegalChat`.

**RAG path (non-obvious).** RAG is reached indirectly:

```
enhanced_app → LegalChatbot(rag_index_path="./data/rag_index")
             → set as MultilingualLegalChat.base_chatbot
             → LegalChatbot.chat() → LegalRAG.query()/search()   (src/rag/legal_rag.py)
             → FAISS IndexFlatIP over MiniLM embeddings
             → answer generated by gemma3 via LegalRAG._generate_answer()
```

If `data/rag_index` is missing, `LegalChatbot` loads without RAG and the chat falls back to a generic reply. The fine-tuned Llama summarizer (`src/models/`) is optional and loaded only if `./results` exists. Never make RAG depend on it.

**Section predictor** (`src/legal_sections/section_predictor.py`) doesn't call the LLM:
- `LegalSectionDatabase` is a hard-coded table of IPC/CrPC/Constitution sections.
- `NEW_CODE_MAPPING` maps them to BNS/BNSS. The new codes have been in force since 1 July 2024.
- Confidence = keyword score, blended 70/30 with optional sentence-transformers similarity (skipped if the library is unavailable).
- UI text must use `LegalSection.display_name`, which shows current law first: `"BNS 103 (formerly IPC 302)"`.

**Offline pipeline.** `dataset/` (IN-Abs, IN-Ext, UK-Abs judgment/summary pairs) is read by:
- `src/data/data_loader.py` → `scripts/preprocess_data.py` → `data/processed/*.json`, used for fine-tuning;
- `scripts/build_rag_index.py` → `data/rag_index/`.

Chunking and retrieval settings are in `config/rag_config.yaml`; model and training settings are in `config/*.yaml`.

**Evaluation.** `src/evaluation/comprehensive_evaluator.py` runs the app's metrics. Bias scoring needs `predicted_labels`/`true_labels`, and returns score 0 with confidence 0 when they're missing; never return a fixed placeholder. `src/utils/evaluation.py` is a separate standalone script for evaluating a fine-tuned model (see STEPS.md).

## Repo conventions and gotchas

- **The dataset is not committed.** It's 313 MB, CC BY 4.0, from [Zenodo record 7152317](https://zenodo.org/records/7152317). `dataset` in `.gitignore` has no trailing slash on purpose, so it also matches a Windows junction or symlink.
- **Anchor root-level ignores.** In `.gitignore`, write `/models/`, not `models/`. A bare `models/` would also hide `src/models/`.
- **Tests import via `sys.path.append(...)`** to the repo root. Tests needing optional heavy packages (`faiss`, `requests`, `langchain_text_splitters`) use `pytest.importorskip`, so one missing package doesn't abort collection.
- **Langchain imports** use `langchain_text_splitters` and `langchain_core.documents`; the old `langchain.text_splitter` path is removed in current releases.
- **CI** (`.github/workflows/tests.yml`) installs CPU-only torch and then `requirements.txt` on Python 3.12.
